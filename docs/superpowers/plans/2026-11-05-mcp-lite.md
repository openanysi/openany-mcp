# MCP Lite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add bounded discovery and execution without changing existing MCP entry points.
**Architecture:** Optional discovery data on immutable catalog snapshots; static three-tool MCP view sharing direct execution. Public documentation ships in the same service.
**Tech Stack:** Go, existing SDK/pgx/jsonschema; no new dependencies.
**Spec:** docs/superpowers/specs/2026-11-05-mcp-lite-design.md

## Global Constraints

- No gateway/naming changes, business DB writes, credential changes or paid supplier calls.
- Native inline execution, one independent review at the end. Implementation and normal main integration/push already authorized in this chat; no repeated approval menu.
- MCP_LITE_ENABLED defaults true per user follow-up. Disabled preserves original query and tooling.
- Preserve exact schemas, credentials, HTTP encoding and direct catalog hash.

## Review Focus

- Optional price failure/blocking must not fail core refresh/readiness.
- Supplier data and raw credential-bearing metadata must never be returned.
- Stale versions, replaced/unavailable APIs and malformed nested input must never dispatch.
- Search cursors must bind query/provider/version and never expose full schema by listing.
- Shared concurrency, per-call credentials and immutable snapshot semantics must hold across views.
